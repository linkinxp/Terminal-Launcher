# Terminal Launcher: panels and widgets round design

Date: 2026-10-23. Status: draft for user review. Extends the v1, cyberpunk and wallpaper specs in this folder; where they disagree, this document wins. Design approved in chat 2026-10-23. Built in this order, one commit per part: (1) panel framework + calendar panel, (2) weather panel, (3) real widget hosting.

## Goal
Add the panels from the user's original reference (calendar agenda, weather) in the launcher's terminal style, and let the user put real Android widgets (for example the Garmin widgets) on home pages. Personal use on the user's Pixel 10 Pro (Android 17). Version 0.4.0.

## Rule changes
- Permissions added: `READ_CALENDAR` (runtime, requested the first time `panel cal on` runs) and `INTERNET` (normal, install-time; weather only). v1's "no network" rule no longer applies.
- Reserved folder-name words gain `panel` and `wx`. The help text is re-flowed (related commands merged) so it still fits the 12-line output panel.
- Panels sit on page 1 under the `sys` panel in the order `cal`, `wx`; both default off.

## 1. Panel framework and calendar panel
- Commands: `panel` (lists `cal on|off`, `wx on|off`), `panel cal on|off`, `panel wx on|off`. Unknown name: `panel: <x>: no such panel (cal wx)`; missing or invalid value: `usage: panel <cal|wx> on|off`. Saved in DataStore (corrupt/missing -> both off).
- `panel cal on` requests `READ_CALENDAR`; if denied the panel shows `cal: no permission (grant in Settings)` and the setting stays on so granting later works.
- Panel `cal`: next 6 events within 7 days, one line each, width 34 characters. `data class AgendaEvent(val title: String, val startMs: Long, val endMs: Long, val allDay: Boolean)`; `fun formatAgenda(events: List<AgendaEvent>, nowMs: Long, zone: java.time.ZoneId, maxLines: Int = 6, width: Int = 34): List<String>`.
  - Sorted by start; events already ended are dropped; an ongoing event starts with `now`; otherwise the label is `today`, `tmrw` or the lowercase English weekday (`tue`), then the 24h time `HH:mm` (or `all day`), two spaces, then the title cut with `…` to fit `width`. Blank title -> `(no title)`. No events -> `["no events"]`.
  - All-day events use `CalendarContract` convention: begin/end are UTC midnights, compared as dates against the local today.
- Source: `CalendarContract.Instances` for `[now, now + 7 days]`, queried off the main thread; refreshed on the minute tick, on screen on, and when the panel is switched on.

## 2. Weather panel
- Data: Open-Meteo (no account, no key). Forecast: `https://api.open-meteo.com/v1/forecast` with `current=temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m,wind_direction_10m,is_day`, `hourly=temperature_2m,weather_code`, `daily=temperature_2m_max,temperature_2m_min`, `timezone=auto`, `forecast_days=2`, `temperature_unit=fahrenheit` only for `f`. Geocoding: `https://geocoding-api.open-meteo.com/v1/search?name=<city>&count=1&language=en&format=json`.
- Privacy: only the latitude and longitude of the chosen city (and the city name for the one-time search) leave the phone. No location permission is used.
- Commands: `wx` (refresh now, show status/last error in the output panel), `wx city <name>` (geocodes once, saves name + latitude + longitude, switches the panel on), `wx units c|f` (default `c`). Not found: `wx: city <name>: not found`; no network and no cache: `wx: offline`; bad input: usage message.
- Pure model: `data class HourPoint(val hour: Int, val temp: Double, val code: Int)`; `data class Forecast(val temp: Double, val humidity: Int, val code: Int, val windKmh: Double, val windDeg: Int, val isDay: Boolean, val high: Double, val low: Double, val hours: List<HourPoint>, val fetchedAtMs: Long)`; `fun parseForecast(json: String, fetchedAtMs: Long): Result<Forecast>` (`hours` = up to 6 points every 3 hours after `current.time`; missing/odd fields fail, never throw); `enum class Condition { CLEAR, PARTLY, CLOUDY, FOG, DRIZZLE, RAIN, SNOW, SHOWERS, THUNDER }`; `fun conditionOf(code: Int): Condition` (WMO: 0 CLEAR; 1-2 PARTLY; 3 CLOUDY; 45,48 FOG; 51-57 DRIZZLE; 61-67 RAIN; 71-77 and 85-86 SNOW; 80-82 SHOWERS; 95-99 THUNDER; anything else CLOUDY); `fun asciiIcon(c: Condition, isDay: Boolean): List<String>` (5 lines, at most 12 columns, printable ASCII, a different night variant for CLEAR and PARTLY); `fun formatWeather(city: String, f: Forecast, fahrenheit: Boolean, nowMs: Long): List<String>` (icon left; right: `<temp>° <condition words>`, wind as compass point + speed, humidity, high/low, the 3-hour strip, and `updated 12m ago` last; every line at most 40 columns).
- Fetching: `HttpURLConnection`, 10 s timeouts, on `Dispatchers.IO`, every 30 minutes while the launcher is resumed and the panel is on, and on `wx`, city change and units change. The last good response (JSON + time) is cached in DataStore and shown immediately, also offline; a failed fetch keeps the cache and shows `updated <age> ago`.

## 3. Real widget hosting
- Model: `Item.Widget(val id: Int, val provider: String, val size: WidgetSize)` where `enum class WidgetSize { SMALL, MEDIUM, LARGE }` and `provider` is the flattened `ComponentName`. `HomeLayout` gains `addWidget(page: Int, widget: Item.Widget)`, `removeWidget(id: Int)`, `resizeWidget(id: Int, size: WidgetSize)` and `pruneWidgets(providers: Set<String>): Pair<HomeLayout, List<Int>>` (returns the layout without widgets of uninstalled providers and the removed ids so their host ids can be deleted). Saved layouts without widgets decode unchanged (format version stays 1; an added `"widget"` item type). Widgets are not pinnable to the dock and not in folders.
- Height: `fun widgetHeightDp(providerMinHeightDp: Int, size: WidgetSize): Int` = `max(providerMinHeightDp, 96 / 192 / 288 for SMALL / MEDIUM / LARGE)` capped at 400.
- Flow (Android): edit mode gets `[+widget]` per page, listing installed providers (label and package). On choice: `AppWidgetHost.allocateAppWidgetId`, `AppWidgetManager.bindAppWidgetIdIfAllowed`; if refused, launch the system `ACTION_APPWIDGET_BIND` prompt; if the provider has a configure activity, `startAppWidgetConfigureActivityForResult`; on success add `Item.Widget` (default MEDIUM) to the layout, on cancel or failure `deleteAppWidgetId` and a message `widget: <label>: not added`. Removing a widget deletes its host id.
- Rendering: `AppWidgetHostView` through `AndroidView`, inside a `TermPanel` titled with the lowercase provider label, fixed height from `widgetHeightDp`; widget options are updated with the panel's width/height in dp. The widget keeps its own look. `AppWidgetHost` (fixed host id) `startListening` in `onStart`, `stopListening` in `onStop`.
- Edit mode per widget: `[S] [M] [L]` size, `[up]/[down]` page order inside the page is out of scope; `[rm]` remove.
- Pages scroll vertically when their content overflows (`verticalScroll(enabled = maxValue > 0)`), so a page without overflow does not swallow the drawer's swipe-up; the status line/dock/prompt area always accepts the swipe-up. If a page overflows the user opens the drawer from the bottom area.

## Architecture
Pure, JVM-tested units: `panel/PanelSettings.kt` (`PanelSettings(cal: Boolean = false, wx: Boolean = false)`, `applyPanel(current, name: String?, on: Boolean?): Result<PanelSettings>`, `describe()`), `Command.Panel(name: String?, on: Boolean?)` and `Command.Wx(sub: String?, arg: String?)` in the parser, `calendar/Agenda.kt` (`AgendaEvent`, `formatAgenda`), `weather/Forecast.kt` (`parseForecast`, `Condition`, `conditionOf`), `weather/WeatherArt.kt` (`asciiIcon`), `weather/WeatherFormat.kt` (`formatWeather`, `compass(deg: Int): String`), `weather/WxSettings.kt` (`WxSettings(city: String?, lat: Double?, lon: Double?, fahrenheit: Boolean = false)`, `applyWx` for the `units` and `city` bookkeeping), `layout/HomeLayout.kt` (widget operations), `layout/WidgetHeight.kt` (`widgetHeightDp`). Android layers (build + JVM screenshots + on-device): `calendar/CalendarRepository`, `weather/WeatherRepository` (HTTP, geocoding, cache), `widgets/WidgetHostController` (allocate/bind/configure/delete, listing providers), `ui/CalPanel`, `ui/WxPanel`, `ui/WidgetPanel`, edit-mode additions, `MainActivity` (permission and bind/configure result launchers, host lifecycle), Prefs additions (panels, weather settings + cache), ViewModel state and commands.

## Error handling
- Calendar permission denied or query failure: the panel shows `cal: no permission (grant in Settings)` / `cal: unavailable`; never a crash.
- Weather: network error, HTTP error status, malformed JSON, or missing fields never throw into the UI; the cache or a one-line error is shown.
- Widgets: a provider that crashes shows Android's own error view; an uninstalled provider's widgets are removed and their host ids deleted on the next refresh; bind refused or configure cancelled leaves the layout unchanged.
- Corrupt stored panel/weather settings fall back to defaults (panels off, no city).

## Testing
- JVM unit tests: `applyPanel` and parser (`panel`, `panel cal on`, `PANEL WX Off`, `wx`, `wx city São Paulo`, `wx units f`) and reserved words; `formatAgenda` (sorting, ended events dropped, `now`/`today`/`tmrw`/weekday labels, all-day, truncation with `…`, blank title, empty list, a zone with DST, maxLines); `parseForecast` against a recorded Open-Meteo sample (every field, 6 hour points, current hour found, missing field -> failure, garbage -> failure); `conditionOf` for every listed code and unknown codes; `asciiIcon` (5 lines, at most 12 columns, printable ASCII, night variants differ); `formatWeather` (lines at most 40 columns, units f/c, `updated` age text, wind compass); `compass`; layout widget operations (add to a page and to a missing page, remove, resize, prune returns removed ids, encode/decode round-trip, old data decodes); `widgetHeightDp` (minimum wins, cap 400).
- JVM screenshots (Roborazzi): home with both panels (several themes), the cal panel empty / permission denied, the wx panel with art for each condition group, the edit-mode widget list, a stand-in widget panel.
- On device (user): calendar permission prompt and real events, a real weather fetch for a city, binding/configuring/displaying a real widget (for example the Garmin widgets), resize and remove, page scrolling versus the drawer swipe-up.

## Out of scope
Notifications feed, media controls, quick toggles, widgets on the dock or in folders, widget drag reordering, location-based weather, weather alerts, multiple cities, calendar write access.
